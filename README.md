# GitScholar

GitHub に置いた論文・研究ノート・Jupyter Notebook・分析コードを、iPad や Android タブレットから読み書きできるアプリです。AI に「この論文のこの部分を説明して」「このメモを直して」と頼むこともできます。

研究室やゼミで資料をリポジトリで共有している人向けに作っています。PCを開かなくても、手元のタブレットで論文を読み、マーカーを引き、メモを書いて、そのままGitHubに反映できます。

## できること

**読む**

- PDF（ページ移動、ピンチズーム、本文検索、テキスト選択）
- Markdown（表・数式・リポジトリ内の相対リンクと画像に対応）
- Jupyter Notebook（セル単位の表示、出力も見える）
- コードと設定ファイル（`.py`, `.R`, `.qmd`, `.bib`, `.yaml` など。色分け表示）
- 画像（png, jpg, gif, svg, webp）
- Git LFS に置かれたファイルも開けます

**書き込む**

- PDFにマーカーを引く。縦書きのPDFにも対応しています
- PDFを読みながら、入力バーからメモを書く。同じ名前の `.md` ファイルに追記されます
- Markdown・テキスト・Notebook の編集
- ファイルの新規作成、名前の変更、フォルダ間の移動、削除
- 別のリポジトリへのファイルのコピー（読み取り専用の資料を自分のリポジトリに持ち出せます）

変更はいったん「保留中の変更」として端末に溜まります。差分を確認してから、メッセージを付けてまとめてコミットします。**承認するまでGitHubには何も送られません。**

**AIに頼む**

開いているファイルや選択範囲について質問できます。AIはリポジトリ内を検索して、修正案を出します。修正は提案として届き、差分を見て承認するまで反映されません。コミットも、AIが依頼することはできますが、実行はあなたの操作です。

提供元は Anthropic・OpenAI・OpenRouter・OpenAI互換の自前サーバから選べます。**APIキーは各自で用意してください**（従量課金です）。キーは端末内にのみ保存されます。

**そのほか**

- GitHub の Discussion と Issues の閲覧、コメント投稿、絵文字リアクション
- よく使うリポジトリのピン留め（最大10件）
- オフライン保存（出先や機内で読めるように、リポジトリやフォルダをまとめてダウンロード）
- 他のアプリで見かけた GitHub のリンクを、共有メニューから GitScholar で開く
- Jupyter Server につないでセルを実行（任意。接続先は設定画面）

## 動作環境

| | |
|---|---|
| Android | Android 9 以上 |
| iPad / iPhone | iPadOS / iOS 16 以上 |
| 必要なもの | GitHub アカウント |
| AIを使う場合 | 利用する提供元のAPIキー（任意） |

画面は iPad などの大きい画面では「ファイル / ビューア / AI」の3分割、スマートフォンでは下のタブで切り替えます。日本語と英語に対応しています（既定は端末の言語）。

## インストール

**まだストアには公開していません。** 配布しているAPKファイル、またはPlayストアのクローズドテストの招待から入れてください。

### Android（APKファイルで受け取った場合）

1. 受け取ったAPKファイルをタップする
2. 「この提供元のアプリはインストールできません」と出たら、設定画面に移動して、APKを開いたアプリ（Chrome、Discord、ファイルなど）にインストールを許可する
3. 「アプリをスキャンしますか？」や「開発元が認識されていません」と出たら、**詳細 → インストール** を選ぶ

警告が出るのは、Playストアを経由していないアプリに対して常に表示されるものです。

すでにGitScholarが入っていて「アプリがインストールされていません」と出る場合は、配布元の違うものが入っています。一度アンインストールしてから入れ直してください。その際、サインインと端末内のキャッシュは消えます。

### Android（クローズドテストの招待を受け取った場合）

招待メールのリンクからテスターに参加し、そこからPlayストアでインストールします。以後の更新はストアから届きます。

### iPad / iPhone

現在はMacからの直接インストールのみです。[DEVELOPMENT.md](DEVELOPMENT.md) の手順が必要になるので、管理者に相談してください。

## 最初に行うこと

1. アプリを開いて **GitHubにサインイン** します。画面にコードが表示されるので、「ブラウザで開く」を押して、GitHubのページにそのコードを入力します。パスワードをアプリに入力することはありません
2. リポジトリの一覧が出たら、使うものを選びます
3. AI機能を使う場合は、設定画面で提供元を選び、APIキーを登録します

### 組織（Organization）のリポジトリが見えないとき

研究室の組織に置いたリポジトリが一覧に出ないことがあります。GitHubの組織には、外部のアプリからのアクセスを制限する設定があり、**承認されるまでそのリポジトリは「無いもの」として扱われます**。エラーも出ないので、気づきにくい挙動です。

承認は組織のオーナーが一度行えばメンバー全員に適用されます。見えない場合は組織の管理者に連絡してください（管理者向けの手順は [DEVELOPMENT.md](DEVELOPMENT.md) にあります）。

## 困ったときは

**変更したのにGitHubに反映されない**

変更は「保留中の変更」に溜まります。変更一覧を開いて、コミットメッセージを付けてコミットしてください。

**コミットでエラーになる**

誰かが同じファイルを先に変更していると競合として止まります。別のファイルなら自動で続きます。また、書き込み権限の無いリポジトリでは、コミットの時点でエラーになります。

**PDFが開けない**

100MBを超えるファイルは開けません。それ以外で開けない場合は、ファイル名を添えて連絡してください。

**サインアウトされてしまう**

GitHubのトークンは一定時間で期限が来ますが、アプリが自動で更新するので、通常はサインインが続きます。それでもサインアウトする場合は、設定 → **サインインの記録** を開いてコピーし、その内容を添えて連絡してください。原因の切り分けに使えます。記録にトークンそのものは含まれません。

**端末の空き容量が気になる**

設定 → キャッシュ で使用量を確認し、リポジトリ単位で削除できます。上限も変更できます。オフライン保存したファイルは自動削除の対象外です。

## まだできないこと

- フォルダごとの移動、複数ファイルの一括操作
- Git LFS のファイルの**編集**（閲覧はできます。LFS管理下のファイルへの書き込みは、理由を示して止まります）
- プルリクエストの作成とレビュー
- 手書きの注釈
- iOSで、GitHubのリンクをタップしてこのアプリで開くこと（OSの制約です。共有メニューからは開けます）

## プライバシー

あなたのデータが送られる先は、GitHub と、あなたが設定したAI提供元だけです。開発者がデータを受け取ることはありません。

AIに送られるのは、添付したファイルや選択範囲、会話の履歴だけです。リポジトリ全体が勝手に送られることはありません。GitHubのトークンとAPIキーは、端末のセキュアストレージ（iOSのキーチェーン、Androidの暗号化領域）にのみ保存されます。

詳細は [PRIVACY.md](PRIVACY.md) にあります。
