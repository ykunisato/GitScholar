# 手動テストチェックリスト（実機）

自動テストで検証できない項目（ネイティブプラグイン、実サービス、性能、アクセシビリティ）を、リリース前に iPad と Android タブレット、iPhone と Android スマートフォンで確認する。結果は日付・端末・OSバージョンとともに `docs/perf_log.md` に記録する。

## 準備

- [ ] GitHub OAuth App（Device Flow 有効）の Client ID で `flutter run --dart-define=GITHUB_CLIENT_ID=...`
- [ ] テスト用リポジトリ: `papers/*.pdf`（テキスト抽出可能なもの、50MB級を1つ）、`notes/*.md`（数式・相対リンク・画像）、`notebooks/*.ipynb`（画像・HTML・error出力、500セル級を1つ）、`analysis/*.R`、`.gitscholarignore`
- [ ] Anthropic API キー、（Phase 3）https の Jupyter Server とトークン

## 認証・リポジトリ（UC-1 前半）

- [ ] サインイン: コード表示、コピー、ブラウザで開く、認可後に自動でリポジトリ一覧へ
- [ ] アプリ再起動後もサインイン状態が保たれる
- [ ] 認可後にアプリへ戻ると数秒以内にリポジトリ一覧へ進む（Android 実機で要確認）
- [ ] 認可後にアプリを終了して開き直しても、サインインが完了する
- [ ] GitHub 側でトークンを取り消す → 次の操作でサインイン画面に戻る
- [ ] 1000件級のアカウントで一覧・検索・並び替えが固まらない
- [ ] 直近のリポジトリが起動時に復元される（FR-14）

## 閲覧

- [ ] PDF: ファイルを開いた直後にエラーが出ない（検索補助の初期化順序の回帰確認）
- [ ] PDF: ページ送り、ピンチズーム、検索ヒットのハイライトと前後移動、テキスト選択、目次、最後のページの記憶
- [ ] 50MB の PDF が 3 秒以内に最初のページを表示する（NFR-12）
- [ ] Markdown: 表、タスクリスト、コードハイライト、`$...$` / `$$...$$`、相対リンクでファイルが開く、相対画像
- [ ] Quarto/Rmd: フロントマターが折りたたみ表示される
- [ ] Notebook: 画像出力、HTML出力（既定はボタン、表示時 JavaScript 無効）、error出力、`outputs_hidden`、500セルでスクロールが滑らか（NFR-13）
- [ ] HTML 出力の「JavaScriptを有効にする」は確認ダイアログを経る。外部リンクをタップしても遷移しない
- [ ] コード: ハイライト、行番号、検索（Cmd/Ctrl+F）、折り返し設定
- [ ] 10,000 エントリのツリーで 60fps スクロール（NFR-11）
- [ ] キャッシュ済みで起動 → ツリー表示まで 2 秒以内（NFR-10）
- [ ] 機内モード: キャッシュ済みファイルを閲覧・編集できる。コミットはエラーになり変更は残る（NFR-20）
- [ ] PDFでテキストを選択すると選択メニューが出る。エラー表示にならないこと
- [ ] 選択メニューまたはツールバーのマーカーから色を選ぶとハイライトが引かれる。ページを移動して戻っても残る（FR-90）
- [ ] マーカー一覧から該当ページへ移動でき、削除するとハイライトが消える。すべて消すと `<pdf名>.annotations.json` の変更も消える
- [ ] PDF下部の入力バーにメモを書くと `<pdf名>.md` が作られ、ページ番号付きで追記される。2件目は末尾に追加される（FR-96）
- [ ] 選択範囲があるときにメモを書くと、引用が一緒に記録される
- [ ] 変更一覧に注釈ファイルとメモファイルが並び、通常どおりコミットできる

## スレッド（FR-97, FR-98）

- [ ] ボトムナビの [スレッド] で Discussion が開く。初回は Discussion であること
- [ ] [Issues] に切り替えると Issues が並ぶ。アプリを開き直すと前回の選択が復元される
- [ ] Discussion が無効なリポジトリでは、その旨と [Issues] への切り替えボタンが出る
- [ ] スレッドを開くと本文とコメントが表示され、GitHubの表示と一致する
- [ ] コメントを投稿すると画面に追加され、GitHub側にも反映される
- [ ] 本文とコメントに [＋] からリアクションを付けられる。件数が増え、自分が付けたものが枠線で分かる
- [ ] もう一度押すと取り消せる。GitHub側の表示とも一致する
- [ ] Issues でも同様にリアクションできる
- [ ] AppBar左上が [一覧] になっており、押すとリポジトリ選択に戻る。リポジトリ名をタップしても同じ

## 編集・コミット（UC-2）

- [ ] Markdown を編集 → 1 秒後に変更マーク → アプリをバックグラウンドにしても保存される
- [ ] CRLF のファイルを編集しても改行コードが保たれる（GitHub の diff で確認）
- [ ] Notebook のセル編集・追加・削除・移動で出力が保たれる
- [ ] 新規・削除・名前変更 → 変更一覧 → 1 コミットで push → GitHub に反映
- [ ] GitHub 上で別ファイルを先に更新 → アプリからのコミットが成功する
- [ ] GitHub 上で同じファイルを先に更新 → 競合ダイアログ → 上書き / 破棄 / 他のみ
- [ ] 新しいブランチへのコミット、ブランチ切り替え

## AI（UC-1 後半, UC-3, UC-5）

- [ ] PDF を開いて「500字で要約」→ ストリーミング表示、文脈バーに PDF 名
- [ ] private リポジトリで初回に送信確認ダイアログ。「今後確認しない」が効く
- [ ] `.gitscholarignore` 対象を開いて質問 → 文脈バーが制限表示、送信内容に本文が含まれない（ログ有効化で確認）
- [ ] Notebook のエラーセルを選択して修正依頼 → 提案カード → 承認前は表示が変わらない → 承認で反映
- [ ] 「precision と personality を扱う資料を探して」→ 回答中のパスをタップするとファイルが開く
- [ ] 停止ボタンで受信済みテキストが残る
- [ ] コミット依頼カード → コミットシートにメッセージとファイルが入る
- [ ] モデル切り替え（Opus 5 / Sonnet 5 / Fable 5.1）と effort 変更で応答する
- [ ] 提供元を OpenAI / OpenRouter に切り替え、モデルIDを入れて接続テストが通る
- [ ] 提供元を切り替えても、それぞれのAPIキーが保持されている
- [ ] OpenAI 互換の提供元でもツール（ファイル読み取り、変更提案）が動く
- [ ] 無効な API キーで分かりやすいエラー
- [ ] AIに質問した後 ← でリポジトリ一覧に戻り、同じリポジトリを開き直すと会話が残っている
- [ ] アプリを再起動して同じリポジトリを開くと、直前の会話が復元される。[＋] で新しい会話を始められる

## 実行環境（UC-4, Phase 3）

- [ ] 設定で接続テスト → バージョンとカーネル一覧
- [ ] Notebook の「すべて実行」→ 出力が更新され変更として残る、エラーで停止
- [ ] 中断・カーネル再起動
- [ ] AI の run_code は確認カードを経て実行される
- [ ] `.qmd` の render が実行ログに残る

## レイアウト・アクセシビリティ

- [ ] iPad 横: 3 ペイン、ペイン幅のドラッグと記憶、AI パネルの開閉（Cmd+J）
- [ ] iPad 縦（600〜840dp）: AI パネルは既定で閉じる
- [ ] スマートフォン: 下部ナビ、ファイルタップでビューアへ切り替わる
- [ ] ダークモード、日本語/英語切り替え
- [ ] VoiceOver / TalkBack で主要ボタンが読み上げられる、最小タップ領域 44dp、文字サイズ最大でも崩れない（NFR-50）
